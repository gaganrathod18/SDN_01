--- transparency check (optional, needs a 3rd terminal) ---

>>> WARNING: the ping in this test MUST target 10.1.2.3 (the VIP), NOT h5's
    real IP (10.0.0.5) directly. Pinging h5 directly is the negative test
    (step 11) and is SUPPOSED to fail with 100% loss / no flow installed --
    that's a different test, not this one. If you ping h5 directly here by
    mistake, you'll get "Destination Host Unreachable" and 0 flow entries,
    which just means the load balancer logic was never triggered (dst IP
    wasn't the service IP), not that anything is broken. <<<

Option A -- xterm (if a display/X11 is available):
  mininet> xterm h5
  # in the h5 xterm:
  tcpdump -XX -n -i h5-eth0

Option B -- mnexec (works headless, no X11 needed):
  # Terminal 2 (mininet CLI) -- get h5's namespace PID:
  mininet> h5 echo $$
  # note the PID printed, e.g. 677677

  # Terminal 3 (any plain terminal) -- enter that namespace:
  sudo mnexec -a <PID_from_above> zsh
  ifconfig                              # sanity check: should show h5-eth0 / 10.0.0.5
  tcpdump -XX -n -i h5-eth0 'icmp'      # 'icmp' filter keeps it to ping traffic only

Then, back in Terminal 2 (mininet CLI), with tcpdump still running:
  mininet> h1 ping -c2 10.1.2.3
